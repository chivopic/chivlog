Supabase 可以先理解成：

> **一个以 PostgreSQL 为核心、帮你把常见后端能力都配好的开发平台。**

它经常被称为 Firebase 的开源替代方案，但它和 Firebase 最大的区别之一，是底层核心数据库就是 PostgreSQL。

## 它给你什么

常用能力基本都已经准备好了：

- PostgreSQL Database
- Auth
- Storage
- Realtime
- Edge Functions
- API

所以做一个小型 Web 产品时，不一定需要先自己搭完整后端。

例如：

```text
Frontend
   ↓
Supabase
├── Auth
├── PostgreSQL
├── Storage
└── Realtime
```

## 为什么值得记住

它特别适合快速做 MVP、个人项目和 AI-native 软件。

比如一个普通应用经常需要：

```text
注册 / 登录
用户数据
文件上传
数据库
权限控制
实时更新
```

这些东西如果全部自己搭，会产生很多基础设施工作；Supabase 可以让这些部分先快速跑起来。

## 和 PostgreSQL 的关系

Supabase 不是自己发明了一套完全新的数据库。

它的核心就是 PostgreSQL，因此仍然可以使用：

- SQL
- 表和关系
- Index
- View
- Trigger
- Function
- Row Level Security

这点很重要，因为你学到的 PostgreSQL 知识可以直接继续使用。

## Auth + RLS 是很关键的组合

例如用户登录后，只应该读取自己的数据。

Supabase 常见的做法是：

```text
Supabase Auth
      ↓
拿到当前用户身份
      ↓
PostgreSQL RLS
      ↓
数据库判断这行数据能不能访问
```

权限不是只依赖前端隐藏按钮，而是可以真正落到数据库层。

## 自托管

Supabase 本身是开源项目，因此除了直接使用 Supabase 托管服务，也可以研究或部署自己的 Supabase 实例。

不过个人项目早期通常没必要急着 self-host，先用托管版把产品做出来更划算。

## 一句话记忆

> **Supabase = PostgreSQL + 一整套现代应用常用的后端能力。**

如果只是想快速做一个需要登录、数据库和文件存储的产品，它通常是一个很值得优先考虑的方案。
